### 1. تقرير العمل المنجز (Project Summary)

قمنا ببناء الجزء الخلفي (**Backend**) لنظام إدارة المستخدمين والتحقق من الحسابات (Authentication & Email Verification System) باستخدام Node.js وExpress وPostgreSQL.

**الخصائص التي تم تنفيذها بنجاح:**

* **تسجيل المستخدمين (Register):** استقبال بيانات المستخدم (الاسم، البريد، كلمة المرور)، وتشفير كلمة المرور، وإنشاء رمز توثيق عشوائي فريد (`verificationToken`) ثم حفظه في قاعدة البيانات.
* **إرسال بريد التفعيل (Email Notification):** استخدام بروتوكول SMTP عبر Nodemailer لإرسال رابط تفعيل مخصص يحتوي على الرمز الفريد إلى بريد المستخدم الإلكتروني.
* **تأكيد الحساب (Email Verification):** معالجة رابط التفعيل، التحقق من وجود الرمز في قاعدة البيانات، تحديث حالة الحساب إلى مُفعل (`is_verified = true`)، وتصفير الرمز لمنع إعادة استخدامه.

### 2. معمارية الباك أند والمنطق البرمجي (Backend Architecture & Flow)

اعتمدنا معمارية **MVC (Model-View-Controller)** المبسطة والمنظمة لضمان فصل المسؤوليات (Separation of Concerns):

```
backend/
├── config/             # إعدادات الاتصال بقاعدة البيانات (db.js)
├── controllers/        # منطق المعالجة والعمليات البرمجية (authController.js)
├── routes/             # توجيه المسارات والمنافذ (authRoutes.js)
├── utils/              # الدوال المساعدة مثل إرسال البريد (sendEmail.js)
├── .env                # المتغيرات البيئية والحساسة
└── server.js           # نقطة الانطلاق الرئيسية لتشغيل السيرفر

```

**دورة حياة الطلب (Request Lifecycle):**

1. **الطلب (Request):** يُرسل العميل (Postman / React / Browser) طلباً هيدروليكياً إلى مسار معين مثل `/api/auth/register`.
2. **المسار (Router):** يستقبل `authRoutes.js` الطلب ويوجهه للدالة المناسبة في `authController.js`.
3. **التحكم والبيانات (Controller & DB):**
* يفحص البيانات المُدخلة، ويتأكد من عدم وجود البريد سابقاً.
* يقوم بتشفير كلمة المرور وتوليد التوكن.
* يتعامل مع PostgreSQL لاستعلام البيانات وتحديثها.


4. **الخدمات المساعدة (Utils):** يتم استدعاء `sendVerificationEmail` لإرسال الرسالة في الخلفية.
5. **الاستجابة (Response):** يُرجع السيرفر كود الحالة (Status Code) ومحتوى JSON للعميل.

### 3. المكتبات المستخدمة ووظيفة كل منها (Dependencies)

* **`express`:** الإطار الأساسي لبناء سيرفر الـ HTTP وتحديد المسارات (Routes) والـ Middleware.
* **`pg` (node-postgres):** المكتبة المسؤولة عن الربط وإجراء الاستعلامات SQL مع قاعدة البيانات PostgreSQL.
* **`bcrypt` / `bcryptjs`:** لتشفير كلمات المرور وسلتها (Hashing) قبل حفظها في قاعدة البيانات لحماية أمن المستخدمين.
* **`nodemailer`:** لإرسال إيميلات التفعيل وتنسيق رسائل HTML عبر خوادم البريد (Gmail SMTP).
* **`dotenv`:** لتحميل المتغيرات البيئية من ملف `.env` (مثل بيانات قاعدة البيانات وكلمات سر البريد) للحفاظ على أمان التطبيق.
* **`crypto` (Node.js Built-in):** مكتبة مدمجة لتوليد رموز عشوائية آمنة ومعقدة (`crypto.randomBytes`) لاستخدامها كـ Verification Tokens.
* **`nodemon` (Dev Dependency):** أداة لتطوير الكود تقوم بإعادة تشغيل السيرفر تلقائياً عند حفظ أي تغييرات.

### 4. رموز حالات الـ HTTP المستخدمة (HTTP Status Codes)

تُستخدم هذه الأرقام لإبلاغ العميل (Client) بنتيجة الطلب الذي أرسله:

* **`200 OK` (نجاح الطلب):**
* **متى يُستخدم؟** عند نجاح العملية وقراءة أو تحديث البيانات بنجاح.
* **في مشروعنا:** عند نجاح تأكيد البريد الإلكتروني في دالة `verifyEmail`.


* **`201 Created` (تم الإنشاء بنجاح):**
* **متى يُستخدم؟** عند إنشاء عنصر جديد بنجاح في قاعدة البيانات.
* **في مشروعنا:** عند تسجيل مستخدم جديد بنجاح في دالة `register`.


* **`400 Bad Request` (طلب غير صالح):**
* **متى يُستخدم؟** عندما يرسل العميل بيانات ناقصة، غير صحيحة، أو عندما يكون التوكن منتهي الصلاحية/غير موجود.
* **في مشروعنا:** عند نسيان إدخال كلمة المرور، أو إذا كان البريد مُسجلاً مسبقاً، أو عند إرسال توكن خاطئ.


* **`404 Not Found` (غير موجود):**
* **متى يُستخدم؟** عندما يطلب العميل مساراً (Route) أو مورداً غير معرف في السيرفر.
* **في مشروعنا:** يظهر تلقائياً إذا حاول العميل طلب رابط مثل `/api/auth/unknown-route`.


* **`500 Internal Server Error` (خطأ داخلي في السيرفر):**
* **متى يُستخدم؟** عند حدوث استثناء أو خطأ غير متوقع في الكود أو انقطاع الاتصال بقاعدة البيانات (`catch (error)`).
* **في مشروعنا:** داخل جميع كتل `try...catch` للتعامل مع أي خطأ برمجي مفاجئ.

### 5. أسس وطريقة كتابة الكود (Code Best Practices)

* **استخدام ES Modules:** التصدير والاستيراد الحديث بأسلوب `import/export` بدلاً من `require`.
* **التعامل مع العمليات غير المتزامنة (`async/await`):** لتسهيل قراءة الكود وتنفيذ الاستعلامات وإرسال الإيميلات دون إغلاق الـ Event Loop.
* **معالجة الأخطاء (`try/catch`):** تغليف جميع العمليات لمنع انهيار السيرفر (Server Crash) عند حدوث أي خطأ وإرجاع رسالة واضحة للمستخدم.
* **حماية البيانات الحساسة (Environment Variables):** عدم كتابة كلمات المرور أو منافذ الاتصال مباشرة في الكود، بل استدعاؤها من `process.env`.
